# Fresh-Session Continuation for pi — retrieval instead of compaction

**Status**: design awaiting approval · **Date**: 2026-10-30 · **Target**: pi extension (pi ≥ 1.4.0)
**Review history**: roborev design reviews 4406 (14 findings) and 4407 (15 findings), all addressed.

## Intent

Replace pi's automatic LLM-summary compaction with retrieval continuation. When the context fills up, the agent continues — **automatically, with no summarization call and no paraphrase** — in a fresh session that retrieves the exact lines it needs from the full record of the old session.

Why: compaction today spends a full-context LLM call (measured elsewhere: 29–38 s, $0.17–1.99 on a ~400k session) and its summary is lossy — the exact error message, file path, or number is often gone. Pi already persists the full record in the session JSONL; the summary step adds cost and destroys fidelity for no benefit when the agent can search the record itself.

## Goals

1. **Fully automatic** at the same trigger points as today's compaction (threshold between turns, pre-prompt check, overflow recovery). Zero user action.
2. **Fresh session file**, created in-process; the interrupted task continues with no user involvement.
3. **Zero LLM summarization** anywhere in the flow. The switch itself costs ~0 s / $0. The only new spend is on-demand recall calls.
4. **Lossless**: every token moved out of context stays reachable verbatim via the recall tools. Reachability across the ancestor chain is *budgeted, never silently truncated* — when a budget cuts the walk, the tools say so (Chain walk semantics).
5. **Self-healing degradation where pi supports it**: if the switch is cancelled (`session_before_switch`), the dispatch is deliberately skipped, or the deferred dispatch never executes, the session continues losslessly in place on pointer + recall context. A throw inside `ctx.newSession` *after teardown begins* is fatal to the process (pi's TUI wrapper exits on command-context errors); the guarantee there is limited to: the old session file remains intact and resumable. Pre-flight validation minimizes the chance of reaching that path.
6. **Exception (explicit)**: in-memory sessions (`--no-session`) have no record to retrieve from; there the extension falls through to pi's default LLM compaction and notifies once. Goals 3–4 hold for persisted sessions, which is the only mode where they are meaningful.

## Non-goals

- No summaries, embeddings, vector indexes, or curated "memory". The model gets the raw record plus tools (the bitter-lesson stance).
- No cross-project knowledge base. `recall` targets only the current session's file and its validated `parentSession` ancestor chain; the `file` argument both tools accept is never a free path — it must exactly match a member of that resolved chain.
- No pi-core changes. Extension only.
- Branch *summarization* (`session_before_tree`) keeps pi's default behavior; out of scope for v1. `/tree` navigation's effects on extension state are defined in flow step 4 (4d) and tested in Stage 3.
- Auto-switch in **print and json modes** is out of scope (pointer compaction only; detection via `ctx.mode` — `ctx.hasUI` cannot distinguish print from RPC). Session switching is exercised in **TUI and RPC** modes.

## Anti-goals

- An LLM call at the threshold moment — that is the thing we are deleting.
- Any path where the agent overflows with no recovery (dead run).
- A paraphrase presented as context.

## Constraints (verified against pi 1.4.0 source)

- `session_before_compact` can return custom compaction content; the returned `firstKeptEntryId` passes verbatim to `appendCompaction`, whose documented signature is `firstKeptEntryId: string | null` — **`null` creates a self-retaining compaction that keeps no preceding entries** (`session-manager.d.ts:271`, `agent-session.js` ~2253/2543). The extension-facing `CompactionResult` type still says `string`, so the `null` needs a cast; Stage 0 verifies retain-none is honored in context.
- **Handler arbitration**: pi runs every `session_before_compact` handler; the last non-cancel result wins, and a `cancel` short-circuits the chain (`runner.js:816–825`). Our compaction can therefore be overridden or cancelled by another handler; the design must not assume its own result landed.
- **Hook error path**: a throwing hook handler is swallowed into `emitError`, after which pi runs the default LLM compaction (`agent-session.js:2544–2580`) — silently reintroducing the summarization call the design deletes. The hook body must be self-guarding.
- Session replacement (`ctx.newSession`) exists only on `ExtensionCommandContext`; lifecycle handlers must not call it directly (deadlock rule). Escape hatch: `pi.sendUserMessage("/fresh", { expandPromptTemplates: true })` — `prompt()` dispatches extension commands **immediately, even during streaming**, before the streaming-queue check (`agent-session.js:1626–1646`).
- The dispatch must be **deferred one tick** (`setImmediate`) from inside the compaction flow, so the command runs on the normal command path, not re-entrantly inside the hook's dispatch stack.
- **Trigger timing**: the threshold check fires between turns (after tool results, before the next LLM call) and after `agent_end` at run boundaries; the pre-prompt check fires at the start of `_prepareRun` — **before the triggering prompt is appended to the session** (`agent-session.js:1480–1486`); overflow recovery fires after the failed run, with the retry pending.
- `newSession` handles an active run: `teardownCurrent` awaits `session.abort()`, so the in-flight turn (including tool results) persists to the outgoing session before replacement (`agent-session-runtime.js:102–110`). `session.abort()` does **not** restore queued steering input to the editor, and in-memory queues (`_steeringMessages`/`_followUpMessages`) are dropped at dispose.
- `hasPendingMessages()` is a point-in-time read; `waitForIdle()` can return while `_deferredSettledActions` still hold prompts; input submitted between any guard check and teardown's dispose is lost. No-drop is therefore **best-effort**, not absolute.
- `withSession` receives a `ReplacedSessionContext` exposing `sendUserMessage`, which **awaits the entire first turn** of the fresh session (`agent-session.js:1910–1939`).
- The TUI wraps command-context session operations in error handling that escalates a throw to a fatal runtime error and process exit (`interactive-mode.js:1484–1491, 1609–1623`).
- `preparation.fileOps` is available only inside the hook; the extraction helpers are not exported by the package, so `/fresh` cannot recompute file lists — the hook must hand them over.
- Fresh session headers carry `parentSession`; entry IDs are unique only within one file (`generateId`, 8 hex chars, `session-manager.js:21–29`), so cross-file fetches must key on file + entry id.
- In-memory sessions (`--no-session`) have no file to recall from: fall through to default compaction.

## Approaches

1. **Manual `/fresh` only** — works, dead simple, but the user wants it as automatic as compaction is today. Rejected.
2. **Same-session retain-none pointer compaction only** — automatic everywhere, zero risk, but not a fresh session file; the user said the fresh session is key. Rejected as primary; retained as the fallback flavor (safety net).
3. **Auto-switch at threshold with a pointer-compaction safety net** — chosen. The hook writes a retain-none pointer compaction (static text, no LLM call); after the compaction is *confirmed landed*, the extension defers a self-invoked `/fresh` command by one tick. Happy path: fresh session file, task continues there. Failed or skipped switch: in-place pointer continuation, task continues anyway. The purist variant (`cancel: true`, no safety net) was rejected: if the deferred switch ever fails, the run continues on a full context, overflows the provider, and a cancelled recovery leaves it dead mid-task. Two review passes refined the mechanics without changing the choice: arming moves to compaction confirmation (extension arbitration), the switch waits for queued input to drain (no deliberate drops), manual `/compact` keeps pi's recent-tail cut, and chain reachability is explicitly budgeted rather than capped by file count.

## How (decided)

### Contract: pi's compaction trigger stays enabled

The extension replaces the **summarization LLM call**, not the trigger machinery. All three **automatic** trigger points (threshold between turns, pre-prompt check, overflow recovery) live inside pi's compaction machinery; with `compaction.enabled: false` those never fire (`_checkCompaction` early-returns, `agent-session.js:2393`), the extension cannot protect against overflow, and a full context dead-ends — the anti-goal. (Manual `/compact` is unconditional in pi: with compaction disabled, bare `/compact` still fires the hook and still gets pointer compaction; `/compact <instructions>` still gets the default LLM summary.) On `session_start`, if compaction is disabled, notify prominently (once; guard with `ctx.hasUI`/`ctx.mode`): *automatic* fresh-session continuation requires the compaction machinery enabled (the default). A private threshold watcher (`turn_end` + `getContextUsage()` + `ctx.compact()`) was rejected as a duplicate engine with its own race surface. Tested in Stage 4a.

### Threshold and overflow flow (`reason: "threshold" | "overflow"`)

1. Hook `session_before_compact` fires. If the session is not persisted → return `undefined` (default LLM compaction; nothing to recall) and notify once.
2. Build the pointer text (below) **inside a self-guarding wrapper**: on any failure (unreadable ancestor, malformed line), fall back to a *minimal pointer* built from data already in hand (old session path + last user message + self-sufficiency line) and notify — never let the hook throw, because a throw silently reverts to the default LLM compaction.
3. Return `{ compaction: { summary: pointerText, firstKeptEntryId: null, tokensBefore } }` → retain-none entry (the documented marker), zero LLM cost. **This is the safety net**: context immediately becomes `[system][pointer]`.
4. **Arm on an automatic-reason `session_compact` confirmation** (`session_compact` event with `fromExtension: true`, our exact summary text, and `reason` `"threshold"` or `"overflow"` — a bare `/compact` writes our pointer compaction too, but must never auto-switch; recovery re-arms from the persisted record, see 4e):

   - **4a. Arming and dispatch guard.** Store the **switch payload** `{ oldSessionPath, pointerTextStatic }` in extension runtime state and move to the **armed** state; only in `tui`/`rpc` modes, `setImmediate`-queue the dispatch (guarded against double-queuing). The dispatch closure is self-guarding on every path (arming, recovery, reload): pi has no is-active probe (every `pi.*` action and every `ctx` getter calls `assertActive()` and throws once invalidated), so the guard is a **local `active` flag** cleared by the `session_shutdown` handler (emitted before invalidation), plus a captured session-file comparison kept as a **defensive assertion that cannot fire in practice** — at arming the two are equal by construction, and every session replacement emits `session_shutdown` before dispose, so a mid-tick switch has already cleared `active`. The send is wrapped in try/catch, treating any `assertActive` throw as *not dispatched* (an uncaught throw would reach the TUI's `uncaughtException` handler and exit the process). Not-dispatched outcome, per case: (a) runtime inactive — nothing can be appended and nothing needs to be; the old file's `armed` record ages out, and the degraded notice fires the next time that session is resumed past the window; (b) the defensive file assertion trips — same as (a). A third guard term covers cancellation: an in-memory **`cancelled` flag** with a defined lifetime — the `session_tree` handler sets it **only when the state machine is `armed` or `in-flight`** (an idle `/tree` is a plain no-op), and it is cleared at every arming (4a arming, 4e re-arm) — never by the in-flight payload refresh (4g) — and again whenever the state machine leaves `armed`/`in-flight` for `idle`: when the guard consumes it, and when the `session_tree` handler itself emits the consumerless notice and returns to `idle` (4d) — so one rewind can never disable later switches or leak a stale refusal into a later manual `/fresh`. The dispatch closure re-checks `active && !cancelled && state ∈ {armed, in-flight}` before the send; `/fresh` re-checks the same predicate immediately after `waitForIdle()` returns **and as the last step immediately before `newSession` on every path** (folded into 4f's commit point). When the flag trips: no send, no `newSession`, exactly one cancellation notice ("fresh-session switch cancelled by tree navigation"), and the state machine returns to `idle` — a manual `/fresh` cancelled this way returns without switching, with that same single notice.
   - **4b. Persisted records and ownership.** The armed state is process-local; at arming, also persist `{ state: "armed", owner, oldSessionPath, pointerTextStatic, armedAt }` with `pi.appendEntry`. The **owner** field names the session file the record was appended to, because pi's fork paths copy custom entries into the new file: a copied record's owner never matches the forked session, so it is a silent no-op, never a spurious notice.
   - **4c. Renderers and caps.** `renderPointerStatic({ oldSessionPath, toc, readFiles, modifiedFiles, instructions })` is rendered at hook time; the same string serves the compaction summary's static part and is persisted as `pointerTextStatic`. **The cap is a property of the function**: every call applies the same truncation (TOC entries first, then file lists; the old session path and instructions are never truncated) and reserves the same volatile headroom against the ~16 KB target — the hook-time summary, the armed-payload prompt, and the manual regeneration are capped identically. `renderVolatileBlock({ lastUserMessage, images, anchor })` is rebuilt from the branch **at each assembly** — hook time for the compaction-summary render (reusing `preparation` data rather than re-reading the branch), `/fresh` execution time for both prompt assemblies — and never persisted; it is capped at assembly against the static headroom (anchor excerpt first, then the last user message per the oversized rule). The structured toc/readFiles/modifiedFiles inputs exist only inside `renderPointerStatic`.
   - **4d. Record resolution and `/tree`.** Records are append-only (pi exposes no delete): clearing appends a `{ state: "cleared", ... }` record for the same session. Resolution, stated once with the mechanism: the **newest custom entry of the state record type on `ctx.sessionManager.getBranch()`** (the leaf path) — never the file-wide newest. `recall`'s abandoned-branch hits are irrelevant here: state records are visible only on the active branch. The **`session_tree` event** (emitted after `/tree` navigation, which emits no `session_start`) is the hook whose **handler has three responsibilities**: it sets the in-memory **`cancelled` flag — only when the state machine is `armed` or `in-flight` (an idle navigation is a plain no-op; 4a defines the flag's reset points) —; when it sets the flag, it appends the cleared record below; and in the no-consumer case it emits the single cancellation notice itself and returns the machine to `idle`. An idle `/tree` (nothing armed or in-flight) writes no records at all. The **consumer** of the flag — the queued dispatch closure, or the `/fresh` parked in its drain, or (when no dispatch is queued and no `/fresh` is parked) the `session_tree` handler itself — emits the single cancellation notice ("fresh-session switch cancelled by tree navigation") and returns the state machine to `idle`. A consumerless cancellation has exactly one reachable case: the re-hydrated `armed` state after a `"reload"` (4e re-hydrates but never dispatches), tracked by a **`dispatchQueued` marker that is process-local, not part of the persisted record (4b), set at every arming/re-arm, cleared with the state machine, and defaulting to `false` when 4e re-hydrates** — when the flag is set with `dispatchQueued` false and no parked `/fresh`, the handler emits the single notice and returns the machine to `idle`. When the flag is set, the handler appends the `{ state: "cleared" }` record after the navigation (`pi.appendEntry` lands on the new active leaf, and in the rewound case it becomes the only resolvable state record on the new path) — pi's `/tree` navigation without branch summarization writes no entry of its own, and every load re-derives the leaf as the file's last entry, so an unwritten record would leave the abandoned armed record resolvable again after a restart. **Residual limitation, stated explicitly**: if the user navigates back onto an armed record's branch, appends new entries there, and then restarts with `session_start` reason `"startup"`/`"resume"` inside the ~1 minute window, the armed record is again the newest state record on the active branch and the switch can re-fire — the handler's cleared record was written on the leaf that was active at navigation time, so nothing on disk covers a branch that later becomes active again. (`"reload"` never re-fires: it re-hydrates but never dispatches, per 4e.) `recall` and the TOC reader skip these custom entries.
   - **4e. `session_start` recovery.** The handler first reads the newest state record on the active branch (per 4d): if none exists, it is not `state: "armed"`, or its **owner** does not match the current session file (a record copied into a fork — the owner check is the only file check, and it is a silent no-op), it is a **silent no-op** — the fresh session after a successful switch (`session_start` reason `"new"`), a fork of an armed session, and any session without native extension state never produce notices or records. Only when an `armed` record is found do the gates apply, with the dispatch **deferred one tick** exactly like 4a (`session_start` is emitted mid-lifecycle, `agent-session.js:2680`, so an inline `newSession` would dispose the runner inside its own emit): `"startup"`/`"resume"` with `ctx.mode` `tui`/`rpc` (the `oldSessionPath` comparison is a defensive assertion that cannot fire, as in 4a) and `now − armedAt` under ~1 minute → re-arm and queue exactly one `/fresh`. **Re-arming is in-memory only** — the record keeps its original `armedAt`, `owner`, and `pointerTextStatic`, so recovery is bounded by the original arming time: a restart loop cannot slide the window, and a second restart after the window degrades once instead of re-dispatching. The record is cleared by that `/fresh` at its commit point, or by the never-dispatched detection — the dispatch has no completion signal, since `pi.sendUserMessage` returns `void`. `"reload"` → re-hydrate the armed state from the record but **never dispatch** (the self-guarding closure treats a stale-runner throw as *not dispatched*; the re-hydrated state guarantees the never-dispatched detection fires at the next `agent_end` and clears the record if nothing ran). `print`/`json` modes → append a cleared record and skip silently, no notice. Any other reason or an expired gate → append a cleared record and emit the degraded notice once.
   - **4f. Clearing rules.** The persisted record is cleared **by `/fresh` itself at the commit point** — immediately before `newSession` is called, after every guard has passed; that append is the **only** clearing action once the guard has passed, so a `session_before_switch` cancellation observed after it writes nothing further — and by every path that ends the state machine without a switch: the degraded notice, pre-flight failure, and the print/json deliberate skip — **except the in-flight refusal**, which leaves the persisted record `armed` untouched (the parked switch still consumes it), and **except the `session_tree` cancellation**, which appends its own cleared record on the new active leaf when the flag was set (4d). `/fresh` step 1 does **not** clear it, so a restart mid-drain finds an `armed` record and follows the standard gates: age under ~1 minute → re-arm and dispatch exactly one `/fresh`; age past it → cleared record + degraded notice once. The armed state plus the next-`agent_end` never-dispatched detection is the fallback if `/fresh` never runs.
   - **4g. State-scoped arming.** In `armed`, store the payload only on a confirming `session_compact` (automatic reasons) and disarm on `session_compact_failed`; in `in-flight` (a drain is running), refresh the payload only from confirming `session_compact` events and **ignore `session_compact_failed`** — that failure belongs to the run being drained and must neither clear the payload the in-flight switch is about to consume nor move the state machine backward; the refresh is **not an arming** and must not clear the `cancelled` flag (4a). A cancelled or overridden hook emits no `session_compact` at all, so nothing arms (`compaction_end` is an AgentSession event, not an extension event). In `print`/`json` modes the state is cleared deliberately: no dispatch, no degraded notice later.
5. `/fresh` executes on the normal command path (details below), consuming the armed payload. It captures the **last user message, its images, and the progress anchor from the persisted branch at execution time** — the static text is the **latest in-memory render** (the arming render, or its in-flight refresh); after a restart with no in-memory payload it is the persisted `pointerTextStatic` (recovery path); and for a manual invocation with no armed payload it is the static render regenerated from the current branch (see `/fresh` step 1) — one tick after the trigger, so the pre-prompt case sees the triggering prompt once it is appended. The spike must confirm this ordering; if the newest message is not yet on the branch when `/fresh` runs, poll the branch for up to ~250 ms; on expiry, build the pointer from the branch's current last user message (the pre-trigger one) plus an explicit notice ("newest prompt not yet persisted; re-read it with `recall { tail }`") — never proceed silently with a stale payload. The timeout case is a Stage 4a pre-prompt test.

### `/fresh` command (auto-invoked at threshold; manually invocable)

1. If the state is already `in-flight` (an automatic or manual switch is parked in its drain), refuse with a notice ("a switch is already in progress") and return — two `newSession` calls from one command context would run the second on an invalidated ctx. Otherwise, move to the **in-flight** state (the dispatch landed; degraded checks are suppressed until completion or failure). The **persisted record stays `armed`** — it is not cleared here; `/fresh` clears it at its commit point (step 5). For a **manual** invocation with no armed payload, regenerate the static part from the current branch (file lists omitted — they cannot be recomputed outside the hook). A second threshold during the drain wait below sees state `in-flight`: its compaction, once confirmed by its own `session_compact`, refreshes the armed payload **process-locally only** — the persisted record keeps its original `armedAt` and `pointerTextStatic`, so the ~1 minute recovery bound never slides — before `/fresh` builds the prompt at the end of the drain; it sets no new state and queues no second `/fresh` (a `session_compact_failed` for it is ignored, per the state-scoped arming rules).
2. **Queued-input drain**: if `ctx.hasPendingMessages()`, `await ctx.waitForIdle()` first, so queued input is delivered and persisted before the switch. Best-effort, not absolute: **re-check `hasPendingMessages()` immediately before `newSession`**; if input slipped in during the race window, it is lost at dispose (not restorable to the editor) — emit a notice: "input submitted during the switch was not delivered and is not in the record; re-send if needed."
3. **Pre-flight validation** before `newSession`: old session file readable, session dir writable, parent path resolvable, **a model is selected and its auth resolves** (a fresh session whose first turn cannot run is a trap). Any failure → notify and stay on pointer mode (the run is safe; no switch attempt).
4. Assemble the pointer prompt: the static part is the latest in-memory render (the arming render, or its in-flight refresh) — only after a restart with no in-memory payload is it the persisted `pointerTextStatic` (recovery path) — plus the volatile block rendered fresh from the persisted branch tail (last user message, images, anchor) under a small incremental budget (~1 s, branch file only).
5. `ctx.newSession({ parentSession: oldSessionPath, withSession: rc => rc.sendUserMessage(pointerPrompt) })`. A `{ cancelled: true }` result or a throw *before* teardown → notify and stay on pointer mode. A throw after teardown is fatal (Constraint); the old session file remains intact and resumable — the stated guarantee.
6. **First-turn failure is handled separately from switch failure**: wrap the `sendUserMessage` call inside `withSession`; a rejection (auth expiry, provider outage) is reported as "switched, but continuation failed" with the old session path and a resume instruction — the user is never stranded silently inside a pointer-only fresh session.
7. **Blocking semantics, decided**: the pointer prompt is sent *inside* `withSession` and awaited (`ReplacedSessionContext.sendUserMessage` awaits the first turn). The automatic chain is fire-and-forget from `setImmediate`, so nothing user-visible blocks. Known consequence: a **manual** `/fresh` submitted over RPC keeps that request open for the duration of the fresh first turn — documented, acceptable. Print/json modes never auto-switch (non-goal).

### Per-trigger switch timing (coherent with the drain rule above)

| Trigger | Hook fires | Switch lands | Waste |
|---|---|---|---|
| Threshold, mid-run | inside `prepareNextTurnWithContext`, immediately before the next assistant request (`agent-session.js:423–431`) | no queued input → immediately; that next request is already in flight and is aborted, its partial output persisted; queued input → after the drain wait; the in-flight request and the rest of the run complete on pointer context — nothing is aborted in this case | no queued input → one small post-pointer request; queued input → the drained run's whole post-pointer remainder (see drain case) |
| Threshold, run boundary | after `agent_end`, before the next run | immediately (already idle) | none |
| Pre-prompt | start of `_prepareRun`, before the prompt is appended | after the new run's first call is aborted (the triggering prompt is persisted first and becomes the pointer's "last user message") | one small post-pointer request |
| Overflow recovery | after the failed run, retry pending | the retried call is aborted; the pointer carries the task | one small post-pointer request |

A second threshold during a drain wait re-fires the hook but the double-queue guard holds; the payload used at execution time is the **latest armed payload** (refreshed only by a confirming `session_compact`), while the last user message, images, and anchor are re-read from the branch at execution time — messages delivered during the drain are in context and reachable via `recall`, but not in the frozen TOC.

**Drain case, costed honestly**: when queued input exists, `/fresh` waits for the run to settle on pointer context before switching, and that remainder is real spend — possibly many turns — bounded only by the user's own queued input. It gets its **own** measured criterion (drain-case latency and cost reported separately in Stage 6) rather than hiding inside the no-queue numbers. Aborting instead of draining was rejected: it drops the queued input (anti-goal). Restart recovery is bounded by the ~1 minute window from arming: a restart during a longer drain yields a cleared record plus the degraded notice (no automatic switch) — the run itself is safe on pointer context.

### Manual `/compact` (`reason: "manual"`)

- Bare `/compact` → **pointer compaction that keeps pi's suggested `firstKeptEntryId`**: the recent tail stays exactly as pi's manual compaction keeps it, and the LLM summary call is replaced by the static pointer. Rationale: manual `/compact` means "shrink this session so I can keep going" — the recent tail is what the user continues from; retain-none would silently change that contract. The threshold path stays retain-none because the fresh session starts from the pointer alone. No auto-switch on manual compaction.
- `/compact <instructions>` → return `undefined` → default LLM compaction: the user explicitly asked for a focused summary; explicit intent wins.

### Chain walk semantics (recall targets, budgets, trust boundary)

- **Targets, by construction**: the current session's file plus its `parentSession` ancestors, walked newest→oldest. `file` is **never a free path** — it is accepted only as an exact match against a member of the resolved chain set; search targets are otherwise the chain walked newest→oldest. `recall` and `recall_get` share **one** validation helper and **one** resolved-set function (single source of truth), so their target sets cannot drift apart.
- **Cycles and duplicates**: ancestry links are on-disk content and may be hand-edited or hostile. Resolution keeps a **visited set of realpath-resolved files** and stops at the first repeat with the same "ancestor chain invalid at `<path>`; not read" notice — a self-referencing or repeating chain can neither loop a cursor-resumed walk nor burn the validation cap. A resumed cursor carries the visited-set digest and is rejected when it does not match the re-resolved chain (single cursor encoding, defined in the reachability bullet above).
- **Trust boundary**: `parentSession` is on-disk content that imported, forked, hand-edited, or third-party sessions can set to any path. Every ancestor target is validated before reading: it must exist, parse as a pi session file (header `type: "session"`), and resolve **inside the session directory** of the current session store. On violation the walk stops at that link, and the result carries a notice ("ancestor chain invalid at `<path>`; not read"). This keeps the read primitive from being reintroduced by the side door.
- **Budgets, never silent truncation**: the pointer-TOC generator and `recall` have *separate* budgets. Pointer generation (runs inside the switch latency budget): ~10 MB, **~2 s elapsed**, depth ~8. Recall tool calls (run inside a normal turn): ~50 MB, ~10 s, depth ~8. When a budget cuts a walk, the output says exactly which older files were **not** scanned/indexed this call, and `recall` hands back a continuation cursor. Reachability degrades loudly, never silently.
- The whole chain is reachable across successive calls: when a budget cuts a walk, `recall` returns an opaque **continuation cursor** encoding `{ visited-set digest, chain index, byte offset, query }`; a follow-up call with `{ cursor }` resumes exactly where the walk stopped, and a cursor whose digest does not match the re-resolved chain is rejected with the "ancestor chain invalid" notice. `file`, when given, must be an exact member of the resolved chain set (validated by the shared helper) and only narrows the search to that member; chain resumption is by cursor, never by an unvalidated path.

### The pointer text (two render functions — static and volatile — assembled at three call sites)

The three assemblies: the **hook-time compaction summary** (`renderPointerStatic` + the hook-time volatile block — the safety net must carry the task context for fallback-mode continuation); the **`/fresh` prompt** (static = the latest in-memory render — the arming render or its in-flight refresh; the persisted `pointerTextStatic` serves verbatim **only on the recovery path** after a restart; volatile rebuilt from the branch); and the **manual `/fresh` prompt** (static regenerated from the current branch — file lists omitted — plus a fresh volatile block). Mechanical, lossless, no LLM. The **whole pointer text targets ~16 KB**: the cap is a property of `renderPointerStatic` — every call applies the same truncation (TOC entries first, then file lists; the old session path and the usage instructions are never truncated) and reserves the same headroom for the volatile block; the persisted `pointerTextStatic` is simply one such render, stored verbatim. The volatile block is capped at assembly against that headroom (anchor excerpt first, then the last user message). The last user message is kept verbatim **unless it alone exceeds the cap** (a pasted log, a huge prompt), in which case it is truncated with a marker and the pointer points to `recall { tail }` for the verbatim text. Image blocks from the **last user message only** are re-attached, capped by count (~4) and total bytes (~1 MB) with a notice naming `recall { tail }` for anything beyond; they do not count toward the text cap.

- absolute path of the old session file, and that the record is complete and verbatim;
- the **last user message verbatim** (captured at hook time for the compaction-summary assembly; at `/fresh` execution time for both prompt assemblies), marked "you were mid-task; resume this"; for the prompt assemblies, re-attach that message's image blocks too (`sendUserMessage` accepts `ImageContent`) so multimodal tasks keep their inputs;
- the **progress anchor** (captured at hook time for the compaction summary; at `/fresh` execution time for the prompts): the last assistant message's text (truncated with a marker if large) plus the ids and file of the last few entries, phrased "your most recent steps are entries X..Y — `recall_get` them before re-doing work" — a mid-run switch resumes from actual progress, not from the task's opening prompt. The anchor snapshot for the prompt assemblies is taken *before* `newSession`, so any partial reply the aborted request emits afterwards is deliberately **not** in the pointer prompt: it lands in the old file, reachable via `recall`, and the anchor names the boundary ("entries after `<id>` are a partial aborted reply");
- a TOC: first line of every user message on the current session's active branch and each ancestor's **leaf path** (the branch pi resumes — the canonical line of history; chain-walk budgets apply; on budget exhaustion the TOC ends with a terminal, actionable marker: "older sessions not indexed here: `<files>` — search them with `recall`, which continues past its budget via cursor" — there is no second indexing pass; the TOC the fresh prompt uses is the latest in-memory render (which the in-flight refresh can supersede), while the compaction entry's own copy stays frozen on its branch) — an index, not a summary; size-capped with a truncation marker. `recall` is deliberately broader than the TOC: it also searches abandoned branches of every file and marks those hits `branch: abandoned`; the pointer text says so ("the index covers the main line; recall also searches abandoned attempts");
- files read/modified, rendered into the static part inside the hook from `preparation.fileOps` (manual `/fresh` omits this list);
- usage instruction: "Do not re-ask the user. When you need the exact error message, file path, number, or prior decision, search the record with `recall` instead of re-deriving — if a search reports unscanned files, continue it with the returned cursor.";
- **self-sufficiency**: "If the `recall` tool is not available (extension disabled), read the session file directly with the read/bash tools." — a resumed pointer-only session still works under stock pi, where the only cost is that the model greps the JSONL itself.

### `recall` tool set (read-only)

- `recall` — search: `{ query?: string, tail?: number, role?: user|assistant|toolResult, limit?, regex?: boolean, cursor?: string, file?: string }`. Exactly one of `query` / `tail` / `cursor` is required (validation error otherwise; a `cursor` call resumes the stored query, honors `role` and `limit`, and rejects `query`, `tail`, and `file` — the cursor fixes its own target). **Search** (`query`): hits with **file reference, entry id, role, timestamp, short excerpt**, plus `nextCursor` when a budget cut the walk. **Literal by default** (the query is escaped and matched as a substring); regex is an explicit `regex: true` opt-in with the query capped (~200 chars); lines larger than ~64 KB are matched in 64 KB chunks with the elapsed budget checked per chunk, and a pathological-pattern fixture must show the elapsed budget bounding the call — a model-chosen regex is a denial-of-service surface otherwise. `limit` is **global across the target set**; a **per-file floor** (~5) applies only while the global limit is unspent (ties broken newest-first), so a 12-file chain cannot make the floor unsatisfiable. Hits are interleaved **newest-first by timestamp** across files. Total result bytes are capped (~32 KB) with a truncation marker; the cap is counted in the cost criterion. **Tail** (`tail: n`): the last `n` entries of the **tail target**, resolved from machine-readable state, never by parsing the pointer's prose. Precedence: if the **current file** has its own `compaction` entry (a fallback-mode pointer landed here), the newest compaction entry wins; otherwise the target is the session header's `parentSession` (after a switch, the old session — *not* the current file, whose tail is already in context and needs no tool); when neither exists — a plain session that never compacted and was not created by `/fresh` — the target is the current file itself. The compaction-boundary rule then applies **to whichever file was resolved as the target**: if the target file has a `compaction` entry, tail returns the last `n` entries of the history **before its newest compaction entry** — in a fresh session whose parent carries the switch's pointer compaction, that yields the parent's real pre-compaction tail, not the pointer text or the aborted fragment. The co-occurrence case — a fresh session that later receives its own pointer compaction — follows the same precedence, and all target cases (own-compaction, parent-with-compaction, plain, co-occurrence) are Stage 1 tail fixtures. `role` filters tail too; `tail` takes no `limit` (`n` bounds it) but shares the byte cap, and a tail entry that alone exceeds the cap is truncated with a `next: { file, entryId, offset }` line exactly like `recall_get`. An optional validated `file` selector (same rules as `recall_get`) overrides the default target.
- `recall_get` — fetch verbatim: `{ file, entryId, offset? }` or `{ around: { file, entryId, before, after }, offset? }` → exact content (full tool results included). The `file` argument is **not a free path**: it must exactly match the current session file or one of the **full resolved `parentSession` ancestry** — validated header-only (exists, parses, inside the session dir), deliberately **not depth-budgeted**, under its own elapsed/byte cap with a notice when that cap is hit. The set is wider than recall's depth-budgeted *walk* on purpose: a cursor-resumed search can return hits from files deeper than the walk budget, and `recall_get` must be able to fetch them (Goal 4). Anything else is rejected with the list of valid targets — the model cannot read outside the chain through this parameter. Paging: `offset` is a UTF-8 byte offset into the entry's (or around-window's) rendered text, so a `next: { file, entryId, offset }` cursor line is directly replayable; `recall_get` shares the ~32 KB result cap with `recall` (counted in the cost criterion); a truncated fetch ends with that `next` line; `around` windows page the same way.
- Implementation: stream the JSONL line-by-line; never load whole files; tolerate a partial trailing line (files are mid-append); search abandoned branches too (a feature: "what did I try before?").

### Degradation and edge cases

- **Switch cancelled, deliberately skipped, or never dispatched** → the safety net already landed; the run continues in place, losslessly. State machine: `idle → armed → in-flight`; arming sets `armed`, `/fresh` execution sets `in-flight`, completion or failure returns to `idle`. The armed state is process-local but persisted via `pi.appendEntry` at arming. The `session_start` recovery first reads the newest state record on the **active branch** — absent, not `armed`, or owned by another file (a fork copy) → silent no-op; a found `armed` record is then **gated on reason, mode, and age** (startup/resume, tui/rpc, `armedAt` within ~1 minute → re-arm and dispatch exactly one `/fresh`; reload → re-hydrate without dispatch, relying on the never-dispatched detection; print/json mode → cleared record, no notice; anything else → cleared record + degraded notice once), so a restart inside the window recovers, a reload never double-dispatches, and an old pointer session resumed later never switches on its own. The never-dispatched case is detected only in state `armed`: if the next `agent_end` (same session file) still sees `armed`, emit the degraded notice and log the captured error. `in-flight` never triggers the notice, so a second threshold during a drain wait cannot produce a false alarm. Cancellation (`session_before_switch`) is observed directly in `/fresh`'s result.
- **Throw after teardown** → fatal (Constraint); old session file intact and resumable; pre-flight + first-turn handling make this path as unlikely as extension code can.
- Overflow recovery (`willRetry: true`) → same flow; if the switch loses the race, the retried turn proceeds on pointer context.
- Double-threshold guard: never queue `/fresh` twice.
- Queued input: drained and persisted before any switch (best-effort with a re-check; residual race window noticed to the user, per `/fresh` step 2).
- Images: `recall` returns text only (documented limit); the switch itself re-attaches the last user message's images.
- Resuming a pointer session with the extension disabled: the pointer text is self-sufficient (pointer section); the full record remains reachable through `/tree` and the file system. The session picker shows pointer text until the session is named; no auto-renaming in v1.
- RPC mode: works headlessly; a manual `/fresh` holds its request open for the fresh first turn (documented). Print/json modes: no auto-switch (pointer compaction only).

### Retention policy

The extension never deletes session files — the record is the product. Each continuation creates one new session file; the switch notice names the new file, and each pointer names its source file, so chain members are identifiable. Disk growth is documented in the README (Stage 6), including manual cleanup via the session picker (`Ctrl+D` → trash). Pruning pointer-only intermediate sessions is explicitly deferred: a wrong prune destroys the record the design exists to keep.

## Success criteria

Measured on a **reference fixture**: a committed generator script produces a ~400k-token persisted session of realistic tool traffic (reads, edits, bash output, errors) with a scripted task in progress; the measuring model and its price table are recorded next to every dollar figure in the README. Procedure: run the fixture, force the threshold, measure.

- Switch latency, trigger → fresh session's first turn starts: **< 5 s** in the no-queued-input case (one pointer-generation budget of ~2 s plus the ~1 s incremental tail read is inside this number). Queued-input case: switch lands at drain + < 5 s; the drained remainder's cost is measured and reported as its own drain criterion, not counted as switch cost.
- **Drain case**: on the reference fixture with a fixed queued-input script (reproducible), the pointer-context remainder and the switch are reported separately — N turns, T seconds, $X. **No upper bound is claimed**: the remainder is the user's own queued input. Stage 6 records the number in the README table.
- Cost per continuation, **no-queued-input case**: **$0** for the switch itself; **< $0.10** total for the fresh first turn plus recall calls, including the ~32 KB result cap (vs. $0.17–1.99 for one compaction), at the README's recorded model and prices. The drain case is judged only by its own reported row, never by this line.
- Replay check: the scripted task interrupted at the threshold completes in the fresh session **without re-asking the user** — the pointer carries the task, recall finds the specifics.
- **Mid-run continuation**: a scripted 30+ tool-call run interrupted mid-run resumes in the fresh session **without repeating completed tool calls** — the progress anchor and `recall { tail }` must suffice, and tail called in the fresh session returns the old session's last entries verbatim.
- **Chain check**: a 12-generation chain (longer than the ~8 depth budget) retrieves a fact from the oldest session — the first call returns the not-scanned marker, cursor continuation reaches the oldest file, and `recall_get` fetches the exact entry. A silent miss fails.
- Disable-compatibility check: the same session resumed with the extension removed still continues the task from the pointer text alone.
